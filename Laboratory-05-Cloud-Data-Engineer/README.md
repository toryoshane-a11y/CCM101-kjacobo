# Laboratory Activity 5: Cloud Data Engineer

## Mission Overview
In this laboratory activity, I set up a proof-of-concept Object Storage environment 
using MinIO, an S3-compatible object storage server. I researched the differences 
between block, file, and object storage, then deployed MinIO using Docker, accessed 
its web management console, created a secure bucket, and uploaded a test file to 
demonstrate the system works.

## Objectives
- Explain the differences between block, file, and object storage.
- Deploy a complex containerized service using environment variables in Docker.
- Access a cloud service running on a specific port via a web browser.
- Create an object storage bucket and upload data successfully.
- Document technical configurations clearly using Markdown.
- Upload evidence and maintain a well-structured GitHub repository.

## Tools Used
- KillerCoda Playground (Ubuntu with Docker)
- Docker CLI
- MinIO (S3-compatible object storage server)
- Git and GitHub for version control and portfolio hosting
- Markdown for technical documentation

## Skills Learned
- How to differentiate between block, file, and object storage and when to use each.
- How to deploy a containerized service using Docker environment variables (`-e` flags).
- How to expose and access multiple container ports (API and web console) through 
  a cloud playground environment.
- How to navigate a web-based object storage management console.
- How to create a storage bucket and upload files through a graphical interface.
