# Mission Reflection

**1. Which cloud infrastructure component do you think is the most important? Why?**

Of the four components I explored, I believe networking is the most important. 
Compute and storage can exist on a single machine, but without networking, none 
of those resources would be accessible to users or connected to the internet. 
Networking is what turns isolated hardware into an actual cloud service — it 
allows users, applications, and other cloud resources to communicate, which is 
the entire point of moving to the cloud in the first place.

**2. How does Linux support cloud computing?**

Linux is the backbone of most cloud infrastructure because it is open-source, 
lightweight, highly customizable, and free to run at scale. Major cloud providers 
like AWS, Azure, and GCP all offer Linux-based virtual machine images, and tools 
like Docker and Kubernetes were built with Linux environments in mind. Working in 
this lab's Ubuntu-based KillerCoda environment showed me firsthand how the command 
line can be used to inspect and manage server resources efficiently.

**3. Why is technical documentation important before deploying infrastructure?**

Documentation ensures that design decisions, resource specifications, and 
configurations are recorded before systems go live. This helps teams avoid 
miscommunication, makes it easier to troubleshoot problems later, and allows new 
engineers to understand a system's setup without needing to ask the original 
architect. In a professional setting, undocumented infrastructure creates risk 
and slows down collaboration.

**4. What new skills did you learn during this laboratory activity?**

I learned how to inspect a Linux server's hardware and software details using 
commands like `lscpu`, `free -h`, and `df -h`. I also learned how to authenticate 
with GitHub using a Personal Access Token, compare cloud provider services, and 
design a basic cloud architecture diagram.

**5. How has your GitHub portfolio improved after completing this mission?**

My portfolio now includes a second structured laboratory folder with organized 
Markdown documentation, screenshots, and a diagram, which demonstrates my growing 
ability to investigate, document, and present cloud infrastructure concepts 
professionally.
